この章では、複雑な図やグラフ、ビジュアライゼーションを作成できる高度な TikZ の機能を紹介します。これらのツールを使うことで、グラフィックの品質と複雑さを大幅に向上させることができます。

## ノードと配置の操作

TikZ のノードは非常に柔軟で強力な要素で、注釈付きの図やチャートの作成に最適です：

```tex
\node[draw, circle] (A) at (0,0) {A};
\node[draw, circle] (B) at (2,1) {B};
\draw[->] (A) -- (B);
```

ノードは名前（`(A)` と `(B)`）で参照でき、簡単に操作やリンクが可能です。

## 複雑な経路と交差点

TikZ は複雑なパスと自動交差検出をサポートします：

```tex
\draw[name path=line1] (0,0) -- (3,3);
\draw[name path=line2] (3,0) -- (0,3);
\fill[name intersections={of=line1 and line2, by={I}}] (I) circle (3pt);
```

ここでは、交点 `I` が自動的に計算され、マークされます。

## 矢印とフローチャート

TikZ は洗練された矢印スタイルを提供し、図やフローチャートに最適です：

```tex
\tikzset{>={Stealth[round, length=4pt, width=6pt]}}
\draw[->] (0,0) -- (2,0);
\draw[<->] (0,1) -- (2,1);
```

矢印ヘッドのスタイルや方向の調整は簡単です。

## マトリックスとアライメント

マトリックスはノードをグリッドや表に整然と配置するのに役立ちます：

```tex
\matrix[matrix of nodes, nodes={draw}, column sep=0.5cm, row sep=0.5cm] (m) {
  A & B \\
  C & D \\
};
\draw[->] (m-1-1) -- (m-2-2);
```

マトリックス要素を簡単に参照して、正確な接続が可能です。

## 数学関数のプロット

TikZ は数式のプロットとシームレスに統合されます：

```tex
\draw[domain=0:4*pi, smooth, samples=100] plot (\x,{sin(\x r)});
```

これにより、数式から直接滑らかで正確なプロットが生成されます。

## 高度なグラフ作成ライブラリ

TikZ には構造化されたグラフと自動レイアウトを処理するための専用グラフライブラリ（`graphs` と `graphdrawing`）が含まれています：

```tex
\usetikzlibrary{graphs,graphdrawing}
\usegdlibrary{force}

\begin{tikzpicture}
  \graph[spring layout, nodes={draw,circle}] {
    A -- {B, C, D},
    B -- {C, D},
    C -- D
  };
\end{tikzpicture}
```

これにより、複雑なグラフの視覚的に魅力的なレイアウトが自動的に生成されます。

## ループ (`\foreach`)

プログラム的に繰り返し構造やグリッドを生成します。

```tex
\foreach \x in {1,2,3}
    \draw (\x,0) circle (0.4);
```

## 座標計算 (`calc` ライブラリ)

中点の計算や投影の例です。

```tex
\usetikzlibrary{calc}
\draw (0,0) coordinate (A) -- (4,2) coordinate (B);
\draw [red] (A) -- ($(A)!0.5!(B)!1cm!90:(B)$);
```

## 外部ライブラリとカスタマイズ

外部ライブラリを使用して TikZ の機能を拡張し、特化した要件に対応できます：

- **pgfplots**: 高度な科学プロット。
- **circuitikz**: 電子回路の回路図。
- **tikz-3dplot**: 現実的な 3D グラフィックの作成。

外部ライブラリを使用するには、単に以下を含めます：

```tex
\usepackage{pgfplots}
\pgfplotsset{compat=1.18}
```
## パフォーマンスとリソース管理

メモリに直接読み込まれるラスター画像とは異なり、TikZの描画は、実行時にTeXマクロインタープリターによって動的に計算されます。最終的なベクターレンダリングが行われる前に、各パス、交点、幾何学的変換が、マクロ展開を通じて順次評価されます。

サーバーサイドの.NETアプリケーションにおいて、複雑なベクター図を含むドキュメントを処理する際は、CPU使用率を最適化し、スレッド枯渇（スレッドスターベーション）を防ぐために、以下のパフォーマンスに関するガイドラインを考慮してください。

|  | **課題** | **ベストプラクティス** |
|---|---|---|
|**マクロ展開とCPUオーバーヘッド**|TikZは、インタープリター方式であるTeXのマクロ展開エンジンに大きく依存しています。深くネストされたループや複雑な幾何学的方程式（アルゴリズムによるプロット描画など）は、ジョブあたりのCPUサイクル数を大幅に増大させる可能性があります。|TikZ内での手続き的な生成処理は、可能な限り軽量に保ってください。数千もの反復要素を生成する場合は、データ駆動型のテンプレートを使用するか、TeXソースの外部で座標をあらかじめ計算しておくことで、マクロ評価の深さを抑えられるか検討してください。|
|**メモリフットプリントとガベージコレクション**|TikZのベクターパスを多数含む大規模な複数ページのドキュメントでは、組版処理中に.NETのマネージヒープ内で巨大な内部オブジェクトツリーが構築されます。|組版ジョブを短命なスコープに分離するか、専用のワーカーインスタンスを使用してください。これにより、出力ストリーム（PDF、XPS、または画像）がフラッシュされた後、ガベージコレクターが効率的にメモリを解放できるようになります。|
|**Webアプリケーションにおける静的図のキャッシュ**|トラフィックの多いWebサービスにおいて、HTTPリクエストのたびに複雑なTikZ図を再コンパイルすると、サーバーのCPUコアがすぐに飽和してしまいます。|図が静的または準静的（管理用ダッシュボードのチャートや標準的な建築図面など）である場合は、`.tex`スニペットを一度だけコンパイルし、生成されたPDFやベクターストリームをメモリ上（`IMemoryCache`などを使用）にキャッシュして、そのキャッシュされたアセットを直接提供するようにしてください。|
|**非同期処理とタイムアウトの管理**|複雑な図に含まれる、最適化されていない、あるいは不適切な形式の再帰的マクロは、無限ループや長時間の処理停止を引き起こす可能性があります。|バックグラウンド ワーカー サービス (Hangfire、Azure Functions、ASP.NET Core のバックグラウンド タスクなど) で `TeXJob` を実行する場合は、タイムアウト時に終了できる別のワーカー プロセスで実行してください。`TeXJob.Run()` は同期的に実行され、キャンセルできません|
