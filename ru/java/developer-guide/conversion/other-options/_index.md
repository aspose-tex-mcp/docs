Каждый пример создаёт `TeXOptions` для LaTeX и задаёт один параметр. Передайте эти настройки в `TeXJob`, предоставьте подходящие входные данные LaTeX и задайте рабочую папку вывода перед запуском задания. Импортируйте `com.aspose.tex.TeXOptions`, `TeXConfig` и классы из выбранного примера: `Interaction`, `com.aspose.tex.rendering.XpsSaveOptions` или `PdfSaveOptions`, а для примера даты — `java.util.Calendar`/`GregorianCalendar`. Обрабатывайте или объявляйте исключения в вызывающем методе. Примеры растеризации и подмножеств шрифтов используют `PdfSaveOptions`; выполняйте вывод через совместимый `PdfDevice`. Примените лицензию согласно [руководству по лицензированию](/tex/{{lang.url-fragment}}java/licensing/).

## Как задать имя задания

Когда мы передаем основной входной файл в качестве имени файла, мы получаем выходные файлы с тем же именем, но с другими расширениями. Движок TeX называет имя входного файла *имя задания* и использует его для выходных файлов, за исключением случаев, когда записываются вспомогательные файлы с явно указанными другими именами. Когда мы передаем основной входной файл как [поток](/tex/{{lang.url-fragment}}java/other-ways-of-main-input/#providing-the-main-input-file-to-the-tex-engine-as-a-stream), движок TeX использует имя задания по умолчанию — *texput*.
В обоих случаях мы можем переопределить имя задания, назначив соответствующий параметр преобразования.

## Как игнорировать недостающие пакеты

Файл LaTeX может ссылаться на пакеты, недоступные в библиотеке Aspose.TeX for Java. Обычно движок останавливается с ошибкой при попытке загрузить такой пакет. Используйте `ignoreMissingPackages(true)`, чтобы пропускать недоступные пакеты. Это не предоставляет команды, которые эти пакеты определяют; входные данные не должны зависеть от таких команд.
