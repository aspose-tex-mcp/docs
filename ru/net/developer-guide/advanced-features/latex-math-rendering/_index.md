## Как преобразовать математическую формулу LaTeX в PNG

Справочный раздел API, связанный с этой темой, находится [здесь](https://reference.aspose.com/tex/net/aspose.tex.features/). Фактически, самый простой способ продемонстрировать функцию **рендеринга математических формул LaTeX** — начать с примера. Вот:

{{< gist "aspose-com-gists" "cd0acc55d1634f17dcf42e02075ca005" "Example-RenderMathToPNG.cs" >}}

Давайте перейдем к деталям. Прежде всего, мы создаем экземпляр [параметры рендеринга](https://reference.aspose.com/tex/net/aspose.tex.features/mathrendereroptions/), аналогичный набору текста TeX/LaTeX. Мы делаем это здесь, одновременно указывая разрешение выходного изображения.

Далее уточняем преамбулу. Преамбула по умолчанию:


```tex
\usepackage{amsmath}
\usepackage{amsfonts}
\usepackage{amssymb}
```

который обеспечивает немного более продвинутую поддержку математических формул, чем базовый LaTeX. Например, вы можете добавить пакет «color», если хотите использовать в формуле собственную подсветку, как мы показали в примере кода.

Затем мы указываем рендереру масштабировать результат на 300%.

Следующие два параметра определяют цвета переднего плана и фона. Те части формулы, которые не покрыты («окрашены») пользовательской подсветкой, будут отображаться цветом TextColor.

Следующая строка примера не имеет особого смысла. Это просто демонстрирует, что вы можете направить вывод журнала в какой-то поток.

И последняя опция «ShowTerminal» позволяет вам переключать запись вывода терминала на консоль.

Метод, который фактически выполняет рендеринг, — это [MathRenderer.Render()](https://reference.aspose.com/tex/net/aspose.tex.features/mathrenderer/render/). Возвращает размер формулы в пунктах.

Поток, в который должно быть записано изображение, принимается методом в качестве второго аргумента. Далее мы создаем поток.

И, наконец, мы вызываем сам метод MathRenderer.Render(), передавая параметры в качестве третьего аргумента. Код LaTeX формулы передается в качестве первого аргумента.

В последних строках примера выводятся два артефакта отрисовки математической формулы — размер формулы и краткий отчет об ошибках (в случае их наличия).

Отличия заключаются в следующем:

* Мы используем класс [SvgMathRendererOptions](https://reference.aspose.com/tex/net/aspose.tex.features/svgmathrendereroptions/) вместо [PngMathRendererOptions](https://reference.aspose.com/tex/net/aspose.tex.features/pngmathrendereroptions/).

* Мы используем класс [SvgMathRenderer](https://reference.aspose.com/tex/net/aspose.tex.features/svgmathrenderer/) вместо [PngMathRenderer](https://reference.aspose.com/tex/net/aspose.tex.features/pngmathrenderer/).

## Создание агента ИИ для рендеринга математических выражений в LaTeX с помощью Aspose.TeX

Для разработчиков, стремящихся инкапсулировать эту функциональность в разговорного или программного агента ИИ, основная инженерная задача смещается от простого выполнения кода к распознаванию намерений, проверке структуры и обработке ошибок во время выполнения.

Ниже приведено предложение по архитектуре рабочего процесса для агента ИИ, который интерпретирует запросы пользователей, создает допустимый синтаксис LaTeX и возвращает полностью отрендеренные визуальные компоненты.

![Блоксхема для рабочего процесса рендеринга математических выражений в LaTeX с помощью ИИ](/tex/images/net/tutorial/blockscheme-for-ai-math-rendering.png)

Как вы можете видеть, агент ИИ для рендеринга математических выражений должен работать как замкнутый цикл обратной связи, состоящий из четырех уровней:

1. Сбор входных данных и синтаксиса (уровень LLM)
Пользователь вводит текст на естественном языке или частично синтаксические выражения (например, «Покажите мне производную уравнения умножения матриц»). Агент преобразует эти запросы в допустимые математические структуры LaTeX внутри структурированной полезной нагрузки JSON, избегая использования оберток Markdown, таких как ````latex`.

2. Проверка и очистка AST (уровень валидатора)
Перед тем, как направлять строки непосредственно в конвейеры выполнения, программный агент проверяет шаблоны токенов, чтобы предотвратить внедрение уязвимостей безопасности или нарушение цепочек выполнения.

3. Конвейер выполнения API (движок Aspose.TeX)
Агент передает очищенный токен непосредственно в бэкэнд-фреймворк обработки, используя правила программного выполнения.
Агент создает экземпляры либо `SvgMathRendererOptions`, либо `PngMathRendererOptions` в зависимости от контекста клиента (например, если пользователь находится на мобильном устройстве или в веб-браузере, используется SVG для оптимальной четкости).

4. Aspose.TeX не выбрасывает исключение, если формула содержит ошибку TeX. Первая ошибка сохраняется в параметре `ErrorReport`, а полный журнал записывается в поток `LogStream`, если он назначен.

Вместо того чтобы незаметно вызывать сбои или аварийное завершение работы пользовательских интерфейсов, агент проверяет `ErrorReport` после каждого вызова `Render()`, создает контекстный цикл и предлагает LLM переписать полезную нагрузку уравнения. Сам результат не является надежным признаком: в зависимости от ошибки изображение может быть создано или оказаться пустым.
