## Texファイル

技術的には、すべてのファイルはTexファイルにすることができます。 *.tex* 拡張子を持つ必要さえありません。 TEXエンジンは、BYTEで入力バイトを読み取り、既知のコマンド(つまり、内部状態にあるコマンド)を認識しようとします。認識されていないコマンドや端末の修正要求に関するエラーを単純に報告します([インタラクティブモード](/tex/{{lang.url-fragment}}net/tex-io/#tex-interaction-modes)で実行されている場合)。ただし、きれいなタイプセットドキュメントのようなものが表示されると予想される場合、入力はTex構文に従い、理想的にはエンジンに既知のコマンドのみが含まれている必要があります。

## Tex入力

TEXジョブは、明示的に指定されたTEXファイルで実行されます。したがって、このファイルを特定のTEXジョブの入力に含めます。さらに、Texには補助入力に関連する4つのプリミティブがあります。

* `\ input <ファイル名>`はファイル名を必要とし、含有ファイルの処理が `\ input`コマンドに到達するとすぐにそのファイルの処理を開始します。補助ファイルの終了が到達すると、処理は `\ input`コマンドを含むファイルに戻ります。
* `\ openin <4-bit-number> = <ファイル名>`もファイル名が必要ですが、ファイルを開き、0から15までの数字にマップします。
* `\ read <number> to <control sequence> `には、ファイルがマッピングされる番号が必要であり、` <control sequence> `が読み取りのリストに対応するように、一度に1行を読み取ります。
* `\ closein <4ビット番号>`数字にマッピングされたファイルを閉じます。

名前が `\input` コマンドと `\openin` コマンドに渡されるファイルも TeX 入力に含まれており、それらを *補助入力* ファイルまたは *依存関係* と呼びます。一方、ジョブに指定されたファイルは *メイン入力* ファイルと呼びます。

4つのコマンドは、メイン入力ファイルまたは補助入力ファイルのいずれかで発生する場合があります。ただし、円形の依存関係に注意してください。

[インタラクティブモード](/tex/{{lang.url-fragment}}net/tex-io/#tex-interaction-modes)で実行する場合、エラーが発生した場合、TEXエンジンは端末で修正を要求します。この時点で、誤ったコマンドを新しいコマンドに置き換えることができます。そして、これは別の方法と、 *端子入力 *と呼ばれるTEXへの入力を提供する最後の方法です。

## TEX出力


[上記で述べたように](/tex/{{lang.url-fragment}}net/tex-io/#tex-input)、TeXジョブは明示的に指定されたファイルで実行されます。ファイルにはタイプセットするデータが含まれない場合があります。入力する文字を生成しない制御シーケンスのみがある場合もあります。ただし、通常はそのようなデータが含まれるため、タイプセットしたテキスト(または、特定のターゲット形式の追加機能に合わせて拡張されている場合は、エンジンと形式で許可されているその他のテキスト)を含むターゲット形式のファイルが生成されます。ファイルの名前は、入力として指定されたファイルと同じになります。このファイルを*メイン出力*ファイルと呼びます。上記で述べたように(/tex/{{lang.url-fragment}}net/aspose-tex-and-object-tex/#object-tex)、元のTeXの場合、これはDVI形式のファイルになります。拡張子なしの入力ファイルと出力ファイルの両方の名前を*ジョブ名*と呼びます。

さらに、Texには補助出力に関連する3つのプリミティブがあります。

* `\ openout <4-Bit-Number> = <ファイル名>`ファイル名を必要とし、ファイルを開き、0から15までの数字にマップします。
* `\ write <number> {token list}`ファイルがマッピングされる番号を必要とし、「トークンリスト」をファイルに書き込みます。
* `\ closeout <4ビット番号>`数字にマッピングされたファイルを閉じます。
 
`\ openout`コマンドに名前が渡されるファイルもTex出力に含まれており、 *補助出力 *ファイルと呼びます。

TEXエンジンが入力を通過すると、いくつかのデバッグ情報が *log*、または *trascript*、ファイルに出力される場合があります。このファイルをTEX出力に含めます。
同時にログファイルに書き込み、TEXエンジンは端末に詳細な情報を出力することができます。これは、TEXエンジンが *端子出力 *と呼ぶ出力を書き込む最後の方法です。

## TEX相互作用モード

TEXジョブは、いつでも4つのインタラクションモードのいずれかで実行されている場合があります。これらのモードは、次のTEXプリミティブによって切り替えられます。

* `\ batchmode`。エンジンはすべての停止を省略し、端子出力を省略するため、入力または出力のいずれかに端子を必要としません。
* `\ nonstopmode`。エンジンはすべての停止を省略し、したがって出力用の端子のみが必要です。
* `\ scrollMode`。エンジンはエラー停止を省略し、入力と出力の両方に端子を必要とします。
* `\ errorStopMode`。エンジンは、やり取りするあらゆる機会に停止します。

Aspose.TeXを使用すると、オブジェクトが作成されているときに、TEXジョブオプションとしてインタラクションモードを指定できます。このモードは、Tex形式を読み込んだ直後にエンジンの内部状態で設定され(どんな形式でもロードされることになっている場合)、エンジンが4つのコマンドのいずれかを遭遇するとすぐに別のモードに切り替えられます。このオプションのデフォルト値は、TEX形式で定義されたインタラクションモードを保持します。フォーマットがロードされていない場合、インタラクションモードは `\ errorStopMode`コマンドによって設定されたものと同じです。
